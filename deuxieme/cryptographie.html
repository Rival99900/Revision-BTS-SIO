🔐 Cryptographie — chiffrer, signer, authentifier

Vocabulaire, chiffrements classiques, RSA avec un exemple chiffré à la main, signature et SSH, hachage des mots de passe, et commandes OpenSSL.

Comment lire cette fiche : les notions viennent de la section « Cryptographie » du Moodle (cours, RSA en Python, OpenSSL, quiz et vidéo interactive). Les explications et les exemples sont reformulés et, quand c'est indiqué, ajoutés par mes soins. Les diapositives du cours restent la référence pour les formulations exactes.
1. Objectifs et vocabulaire

Confidentialité

Seul le destinataire peut lire le message.

Authenticité

On identifie l'expéditeur avec certitude.

Intégrité

Le message n'a pas été modifié en route.

Preuve / traçabilité

L'expéditeur ne peut pas nier avoir envoyé le message (non-répudiation).

Terme Sens
Chiffrement / déchiffrementTransformer le message pour qu'il ne soit lisible que par le destinataire, puis le relire.
CryptanalyseAttaquer un protocole de chiffrement pour retrouver le message ou la clé.
CryptographieL'art de concevoir des protocoles de chiffrement.
CryptologieCryptographie + cryptanalyse.
StéganographieCacher l'existence même du message (bits de poids faible, etc.). Peu fiable : la sécurité ne doit pas reposer sur le secret de la cachette.
Vocabulaire : « cryptage » n'existe pas dans le vocabulaire du cours. On dit chiffrement.
Principe de Kerckhoffs : le message peut tomber entre les mains de l'ennemi. La sécurité ne doit donc jamais reposer sur le secret de l'algorithme : seule la clé doit rester secrète.
2. Chiffrements classiques
Méthode Principe Clé Faiblesse
Atbash Remplace chaque lettre par sa symétrique dans l'alphabet (A↔Z, B↔Y…), soit la lettre de rang 27 − n. Aucune L'algorithme est connu : déchiffrer se fait sans secret.
César Décale chaque lettre de k rangs dans l'alphabet. k (26 valeurs) Quelques essais suffisent.
Substitution monoalphabétique Chaque lettre est remplacée par une autre lettre, selon une permutation fixe. Une permutation de 26 lettres 26! ≈ 4,03 × 10²⁶ clés : pas de force brute, mais l'analyse de fréquences casse le texte s'il est assez long.
Vigenère Polyalphabétique : chaque lettre est décalée selon une lettre d'un mot-clé répété. Un mot (26longueur clés) Répéter la clé donne des régularités ; l'analyse statistique (adaptée par Babbage) casse le chiffre.
Enigma Machine à rotors : la substitution change à chaque lettre. Un tour complet dure 26³ = 17 576 caractères. Réglage des rotors, changé régulièrement Messages standard prévisibles (« Heil Hitler ») et erreurs des opérateurs. Cassée à Bletchley Park, notamment par Alan Turing.
Vernam (masque jetable) Clé aléatoire aussi longue que le message, utilisée une seule fois. Aléatoire, à usage unique Théoriquement incassable, mais pratiquement lourd : générer la clé et la transmettre en sécurité.
Exemple : Vigenère (exemple original)
Message : ATTAQUE Clé : CLE CLE C (la clé est répétée) A + C = C T + L = E T + E = X A + C = C Q + L = B U + E = Y E + C = G Chiffré : CEXCBYG
César en Python
def cesar(texte, decalage): res = "" for c in texte.upper(): if 'A' <= c <= 'Z': res += chr((ord(c) - ord('A') + decalage) % 26 + ord('A')) else: res += c return res cesar("JE CHIFFRE PAR DECALAGE", 3) # 'MH FKLIIUH SDU GHFDODJH'
Piège fréquent : plus la clé est courte et répétée, plus le chiffre est fragile. Pour résister à la statistique, il faut une clé longue, et idéalement jamais réutilisée (Vernam).
3. RSA : chiffrement asymétrique
Idée : deux clés liées mathématiquement. La clé publique circule librement ; la clé privée reste chez son propriétaire. Tout le monde chiffre avec la publique, seul le propriétaire déchiffre avec la privée.
Élément Valeur (exemple du cours) Rôle
Clé publique(e, n) = (3, 55)Chiffrer : c = me mod n
Clé privée(d, n) = (27, 55)Déchiffrer : m = cd mod n
Calculs de l'exemple
Message m 2 3 4 5
Chiffré f(m) = m³ mod 55827915
Déchiffrer le chiffré 2 : f−1(2) = 227 mod 55 = 18. Vérification : 18³ = 5 832, et 5 832 mod 55 = 2.
Génération des clés (étapes)
Étape Calcul
1. Deux nombres premiers secretsp = 5, q = 11
2. Modulen = p × q = 5 × 11 = 55 (publié)
3. Indicatrice d'Eulerφ(n) = (p − 1) × (q − 1) = 4 × 10 = 40 (secret)
4. Exposant publice = 3 (publié), avec pgcd(e, φ) = 1
5. Exposant privéd tel que e × d mod φ = 1 : 3 × 27 = 81 = 2 × 40 + 1, donc d = 27
# Démonstration en Python (la recherche de d est une force brute) p, q = 5, 11 n = p * q # 55 phi = (p - 1) * (q - 1) # 40 e = 3 # clé publique d = next(x for x in range(1, phi) if (e * x) % phi == 1) # 27 chiffre = lambda m: pow(m, e, n) dechiffre = lambda c: pow(c, d, n) print(d, chiffre(2), dechiffre(chiffre(2))) # 27 8 2
Sécurité : si on connaît φ = 40, on retrouve d en quelques calculs. Si on factorise n = 55 en 5 × 11, on retrouve φ, donc d. C'est pour cela que p, q et φ restent secrets.

Nuance : le diaporama dit que la factorisation est « presque NP-complète ». C'est imprécis : aucun algorithme efficace n'est connu sur un ordinateur classique, mais on ne sait pas si le problème est NP-complet. Le diaporama évoque aussi l'ordinateur quantique : l'algorithme de Shor factoriserait efficacement, d'où la menace quantique pour RSA.
RSA en pratique : il est gourmand en calculs (clés de 2048 à 4096 bits). Pour cette raison, on combine souvent les deux : le chiffrement symétrique pour le contenu, et l'asymétrique pour échanger la clé. C'est le principe de SSH et de HTTPS.
4. Signature, authentification et SSH
Usage Clé utilisée Ce que ça prouve
SignatureClé privée (on signe)Le message vient bien de son auteur et n'a pas été modifié.
Authentification (vérification)Clé publique (on vérifie)Celui qui a signé possède la clé privée correspondante.
Commandes OpenSSL (page du Moodle)
# Création de la paire de clés openssl genrsa -out key.priv 4096 openssl rsa -in key.priv -pubout > key.pub # Chiffrement / déchiffrement openssl pkeyutl -encrypt -pubin -inkey key.pub -in fichierclair -out fichierchiffre openssl pkeyutl -decrypt -inkey key.priv -in fichierchiffre -out fichierdechiffre # Signature / vérification openssl dgst -sign key.priv -keyform PEM -sha256 -out signature -binary fichier openssl dgst -verify key.pub -keyform PEM -sha256 -signature signature -binary fichier
Première connexion SSH : l'attaquant peut remplacer la clé publique du serveur par la sienne (man-in-the-middle). Il faut comparer l'empreinte (fingerprint) de la clé avec celle attendue. Le diaporama fait le même rapprochement avec WhatsApp.
5. Hachage et mots de passe
Principe : une fonction de hachage f transforme une donnée en empreinte y = f(x). On ne peut pas la « déchiffrer » : elle sert à comparer.

Stockage

Le système (/etc/shadow sous Linux) ne garde que l'empreinte y, jamais le mot de passe en clair.

Connexion

L'utilisateur saisit x. Le système calcule f(x). Si f(x) = y, connexion acceptée ; sinon, rejetée.

Limite

Un mot de passe courant se retrouve par attaque de dictionnaire (ex. liste rockyou), en hachant chaque candidat. Le hachage ne protège pas à 100 %.

Ajout hors diaporama : pour ralentir ces attaques, on ajoute un sel aléatoire à chaque mot de passe avant de le hacher.
