Le protocole DHCP (Dynamic Host Configuration Protocol, RFC 1533/1534) automatise l'attribution des adresses IP aux hôtes d'un réseau. C'est une extension du protocole BOOTP.

Ce que fournit un serveur DHCP

Informations obligatoires

  • Une adresse IP unique sur le réseau
  • Le masque de sous-réseau
  • La durée du bail (lease time)

Informations optionnelles

  • Adresse de la passerelle par défaut
  • Adresses des serveurs DNS
  • Adresses des serveurs WINS
  • Nom de domaine, NTP…

Avantages du DHCP

  • Distribution d'adresses centralisée
  • Changement de plan d'adressage facilité
  • Gestion des postes itinérants
  • Évite la configuration manuelle poste par poste
  • Évite les conflits d'adresses IP
Fonctionnement DHCP — Les 4 phases (DORA)
1. DHCPDISCOVER
Client → broadcast
src: 0.0.0.0 / dst: 255.255.255.255
+ adresse MAC du client
→
2. DHCPOFFER
Serveur → propose une IP
+ durée du bail
+ adresse IP du serveur
→
3. DHCPREQUEST
Client → accepte la 1re offre
(broadcast pour informer tous les serveurs)
→
4. DHCPACK
Serveur → confirme l'attribution
L'adresse est marquée "utilisée"
💡 Pourquoi le broadcast ? Le client n'ayant pas encore d'IP, il utilise son adresse MAC et envoie en broadcast Ethernet (ff:ff:ff:ff:ff:ff). Tous les serveurs DHCP du réseau reçoivent la demande.
Renouvellement du bail

À 50% du bail

Le client envoie un DHCPREQUEST unicast directement au serveur qui lui a attribué l'adresse pour renouveler le bail.

À 87,5% du bail

Si le renouvellement échoue à 50 %, le client contacte n'importe quel serveur DHCP en broadcast. Réponse possible : DHCPACK (renouvellement) ou DHCPNACK (refus).

À expiration du bail

Le client doit cesser d'utiliser l'adresse IP immédiatement et relancer le processus DORA depuis le début.

Commandes Windows & Agent relais
# Commandes Windows (ipconfig) : ipconfig /all ipconfig /renew ipconfig /release # Équivalent Linux : ifconfig dhclient -r dhclient
💡 Agent relais DHCP : quand le serveur DHCP est sur un autre sous-réseau, un agent relais intercepte le DHCPDISCOVER et le transmet en unicast au serveur DHCP distant.

Le DNS (Domain Name System, RFC 1034 & 1035) est une base de données distribuée et hiérarchisée qui résout les noms de domaine en adresses IP. Les clients DNS sont des solveurs (resolvers), les serveurs sont des serveurs de noms (name servers).

Pourquoi le DNS ?

Nom d'hôte

Alias assigné à un ordinateur pour l'identifier sur TCP/IP. Jusqu'à 256 caractères. Un hôte peut avoir plusieurs noms d'hôtes.

Besoin de résolution

Pour envoyer une trame réseau, il faut l'adresse MAC (via ARP), qui nécessite l'adresse IP. Or l'utilisateur travaille avec des noms → besoin de conversion nom → IP.

4 méthodes de résolution

  • Cache local
  • Fichier hosts
  • Diffusion locale NetBIOS
  • Serveur de noms DNS
Hiérarchie de domaines DNS

Structure arborescente

  • Domaine racine : point (.)
  • TLD : 1er niveau (.fr, .com…)
  • Sous-domaines
  • Dernier niveau : le nom d'hôte

TLD génériques (gTLD)

  • .com — entreprises commerciales
  • .edu — éducation
  • .gov — gouvernement américain
  • .org — organisations non commerciales
  • .net — fournisseurs réseaux
  • .mil — armée américaine

Nouveaux gTLD

  • .biz
  • .info
  • .pro
  • .museum / .coop / .name

TLD géographiques

Codes pays ISO 3166 : .fr, .uk, .de, .jp…

Domaine spécial : in-addr.arpa → résolution inverse.

💡 FQDN = nom d'hôte + nom de domaine complet. Exemple : montblanc.btsig.lmd.fr.
Types de serveurs DNS

Serveur Primaire

Gère directement une ou plusieurs zones. Informations stockées dans des fichiers locaux. Il a autorité sur sa zone.

Serveur Secondaire

Obtient ses données via un transfert de zone depuis le primaire. Rôle : tolérance aux pannes et réduction de charge.

Serveur Cache

N'a aucune autorité. Met en cache les résolutions effectuées pour accélérer les requêtes et réduire le trafic.

Zone d'autorité

Portion de l'arborescence DNS sous la responsabilité d'un serveur.

Une attaque par Déni de Service (DoS) vise à rendre indisponible pendant un temps indéterminé les services ou ressources d'une organisation.

Attaques DoS

SYN Flooding

Exploite le Three-Ways Handshake TCP. Des milliers de paquets SYN avec IP sources invalides/usurpées saturent la file d'attente.

Smurf

Ping ICMP envoyé à une adresse broadcast en falsifiant l'IP source de la cible : amplification et saturation.

Ping of Death

Datagramme IP dépassant 65 536 octets → dépassement de tampon lors du réassemblage.

Teardrop

Offsets erronés dans des paquets fragmentés → chevauchements lors du réassemblage.

LAND

Même IP et même port en source et destination → boucle.

ARP Poisoning

Empoisonnement du cache ARP → Man-in-the-Middle.
