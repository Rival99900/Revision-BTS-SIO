DHCP
"

Le protocole DHCP (Dynamic Host Configuration Protocol, RFC 1533/1534 ) automatise l' attribution des adresses IP aux hôtes d'un réseau. C'est une extension du protocole BOOTP.

Ce que fournit un serveur DHCP

Informations obligatoires

  • Une adresse IP unique sur le réseau
  • Le masque de sous-réseau
  • La durée du bail (lease time)

Informations optionnelles

  • Adresse de la passerelle par défaut
  • Adresses des serveurs DNS
  • Adresses des serveurs WINS
  • Nom de domaine, NTP…

Avantages du DHCP

  • Distribution d'adresses centralisée
  • Changement de plan d'adressage facilité
  • Gestion des postes itinérants
  • Évite la configuration manuelle poste par poste
  • Évite les conflits d'adresses IP
Fonctionnement DHCP — Les 4 phases (DORA)
1. DHCPDISCOVER
Client → broadcast
src: 0.0.0.0 / dst: 255.255.255.255
+ adresse MAC du client
→
2. DHCPOFFER
Serveur → propose une IP
+ durée du bail
+ adresse IP du serveur
→
3. DHCPREQUEST
Client → accepte la 1re offre
(broadcast pour informer tous les serveurs)
→
4. DHCPACK
Serveur → confirme l'attribution
L'adresse est marquée "utilisée"
💡 Pourquoi le broadcast ? Le client n'ayant pas encore d'IP, il utilise son adresse MAC et envoie en broadcast Ethernet ( ff:ff:ff:ff:ff:ff ). Tous les serveurs DHCP du réseau reçoivent la demande.
Renouvellement du bail

À 50% du bail

Le client envoie un DHCPREQUEST unicast directement au serveur qui lui a attribué l'adresse pour renouveler le bail.

À 87,5% du bail

Si le renouvellement échoue à 50 %, le client contacte n'importe quel serveur DHCP en broadcast. Réponse possible : DHCPACK (renouvellement) ou DHCPNACK (refus).

À expiration du bail

Le client doit cesser d'utiliser l'adresse IP immédiatement et relancer le processus DORA depuis le début.

Commandes Windows & Agent relais
# Commandes Windows (ipconfig) : ipconfig /all # affiche toute la configuration IP ipconfig /renew # envoie DHCPREQUEST (renouvellement du bail) ipconfig /release # envoie DHCPRELEASE (libère l'adresse) # Équivalent Linux : ifconfig dhclient -r # release dhclient # renew
💡 Agent relais DHCP : quand le serveur DHCP est sur un autre sous-réseau (le broadcast ne traverse pas les routeurs), un agent relais (configuré sur le routeur) intercepte le DHCPDISCOVER et le transmet en unicast au serveur DHCP distant.
DNS
"

Le DNS (Domain Name System, RFC 1034 & 1035 ) est une base de données distribuée et hiérarchisée qui résout les noms de domaine en adresses IP. Les clients DNS sont des solveurs (resolvers) , les serveurs sont des serveurs de noms (name servers) .

Pourquoi le DNS ?

Nom d'hôte

Alias assigné à un ordinateur pour l'identifier sur TCP/IP. Jusqu'à 256 caractères . Un hôte peut avoir plusieurs noms d'hôtes .

Besoin de résolution

Pour envoyer une trame réseau, il faut l' adresse MAC (via ARP), qui nécessite l' adresse IP . Or l'utilisateur travaille avec des noms → besoin de conversion nom → IP.

4 méthodes de résolution

  • Cache local (volatile, rapide)
  • Fichier hosts (/etc/hosts sur Linux)
  • Diffusion locale NetBIOS (ne traverse pas les routeurs)
  • Serveur de noms DNS ← la solution TCP/IP
Hiérarchie de domaines DNS

Structure arborescente

  • Domaine racine : représenté par un point (.)
  • TLD (Top Level Domain) : 1er niveau (.fr,.com…)
  • Sous-domaines : niveaux inférieurs
  • Dernier niveau : le nom d'hôte

TLD génériques (gTLD)

  • .com — Entreprises commerciales
  • .edu — Éducation
  • .gov — Gouvernement américain
  • .org — Organisations non commerciales
  • .net — Fournisseurs réseaux
  • .mil — Armée américaine

Nouveaux gTLD

  • .biz — Business
  • .info — Information
  • .pro — Professions réglementées
  • .museum / .coop / .name …

TLD géographiques (ccTLD)

Codes de pays ISO 3166 : .fr France, .uk Royaume-Uni, .de Allemagne, .jp Japon…

Domaine spécial : in-addr.arpa → résolution inverse (IP → nom)

💡 FQDN (Fully Qualified Domain Name) = nom d'hôte + nom de domaine complet. Exemple : montblanc.btsig.lmd.fr désigne la machine montblanc dans le domaine btsig.lmd.fr .
Types de serveurs DNS

Serveur Primaire (Principal)

Gère directement une ou plusieurs zones. Informations stockées dans des fichiers locaux . Il a autorité sur sa zone. Seul à pouvoir modifier les données.

Serveur Secondaire

Obtient ses données via un transfert de zone depuis le serveur primaire. Fichiers en lecture seule . Rôle : tolérance aux pannes + réduction de charge sur le primaire.

Serveur Cache

N'a aucune autorité et ne fait aucun transfert de zone. Met en cache les résolutions effectuées. Intérêt : accélère les requêtes, réduit le trafic réseau.

Zone d'autorité

Portion de l'arborescence DNS sous la responsabilité d'un serveur. Un serveur peut gérer plusieurs zones , chacune stockée dans un fichier distinct .

Resource Records (RR) — Types principaux
"

Chaque information élémentaire de la base DNS est un Resource Record (RR) . Format : [domaine] [ttl] [classe] type données

Type RR Nom complet Rôle
SOA Start Of Authority Informations d'autorité sur la zone : serveur primaire, n° de série, intervalles de rafraîchissement et TTL minimum
A Address Associe une adresse IPv4 à un nom de machine (résolution directe nom → IP)
AAAA IPv6 Address Associe une adresse IPv6 à un nom de machine
NS Name Server Spécifie le ou les serveurs de noms de la zone
CNAME Canonical Name Associe un alias au nom canonique d'un hôte (pointé par un enregistrement A)
PTR Pointer Résolution inverse : retrouver un nom à partir d'une IP (utilisé pour la sécurité)
MX Mail Exchanger Désigne le serveur SMTP chargé de recevoir les emails du domaine
⚠️ TTL (Time To Live) : durée en secondes pendant laquelle une résolution peut rester en cache. Plus il est long, moins il y a de requêtes mais plus les changements mettent du temps à se propager.
Fichiers de configuration DNS
# === Fichier named.hosts (zone btsig.lmd.fr) === @ IN SOA bach.btsig.lmd.fr Daniel.Dennet.bach.btsig.lmd.fr ( 32 ; numéro de série (incrémenté à chaque modification) 86400 ; rafraîchissement : 1 fois par jour 3600 ; tentatives de retry : 1 heure 3600000 ; expiration : 42 jours 604800 ; TTL minimum : 1 semaine ) IN NS bach.btsig.lmd.fr ; serveur de noms de la zone Bach IN A 200.100.40.11 ; IP de la machine Bach Escher IN A 200.100.40.12 ; IP de la machine Escher Godel IN A 200.100.40.10 ; IP de la machine Godel www IN CNAME escher ; alias www → escher ftp IN CNAME Godel ; alias ftp → Godel
# === Fichier d'amorçage named.boot (BIND) === Directory c:\winnts\system32\dns Cache. named.ca ; serveurs racine Internet Primary btsig.lmd.fr named.hosts ; zone primaire de ce serveur # === Commandes de vérification === nslookup montblanc.btsig.lmd.fr # résolution directe (nom → IP) nslookup 200.100.40.11 # résolution inverse (IP → nom)
Intégration DNS-WINS (environnement Windows)

Pourquoi combiner ?

DNS mode statique (enregistrements saisis manuellement).
WINS mode dynamique (enregistrements automatiques).
Les deux sont complémentaires dans un environnement Microsoft.

Processus DNS-WINS

  1. Client interroge le serveur DNS
  2. DNS cherche dans sa base → nom non trouvé
  3. DNS convertit la partie hôte en nom NetBIOS
  4. DNS interroge le serveur WINS
  5. WINS connaît le nom → retourne l'adresse IP au DNS
  6. DNS transmet l'IP au client
ATTAQUES RÉSEAU
"

Une attaque par Déni de Service (DoS) vise à rendre indisponible pendant un temps indéterminé les services ou ressources d'une organisation, sans nécessairement accéder aux données.

Attaques DoS — Descriptions détaillées

SYN Flooding (TCP)

Exploite le Three-Ways Handshake TCP (SYN → SYN/ACK → ACK).
L'attaquant envoie des milliers de paquets SYN avec des IP sources invalides ou usurpées . La cible attend des ACK qui n'arrivent jamais → file d'attente de connexions saturée → plantage ou indisponibilité.

Smurf — Attaque par réflexion

L'attaquant envoie un ping ICMP à l' adresse broadcast d'un réseau en falsifiant l'IP source (= IP de la cible). Toutes les machines du réseau répondent en même temps à la cible → saturation du lien.

Ping of Death

Envoie un datagramme IP dont la taille excède 65 536 octets (taille maximale autorisée par IP). Lors du réassemblage → dépassement de tampon → plantage. Systèmes récents non vulnérables

Teardrop — Fragmentation

Insère des informations de décalage (offset) erronées dans des paquets IP fragmentés. Lors du réassemblage côté destination → vides ou chevauchements → instabilité et plantage. Systèmes récents non vulnérables

LAND (1997)

Envoie un paquet avec la même adresse IP et le même port en source ET en destination. La machine tente de répondre à elle-même indéfiniment → boucle → plantage. Systèmes récents non vulnérables

ARP Poisoning (ARP Spoofing)

Exploite le protocole ARP (résolution IP → MAC). L'attaquant envoie des réponses ARP falsifiées aux deux victimes en associant sa propre MAC à leurs IP. Les deux victimes envoient tout leur trafic à l'attaquant → Man-in-the-Middle : écoute, modification.

Tableau récapitulatif des attaques
Attaque Protocole exploité Mécanisme
SYN Flooding TCP Saturer la file d'attente des connexions semi-ouvertes (SYN_RECEIVED)
Smurf (Réflexion) ICMP + Broadcast Amplification par broadcast, IP source usurpée = IP de la cible
Ping of Death ICMP / IP Datagramme de taille > 65 536 octets → buffer overflow au réassemblage
Teardrop IP (fragmentation) Offset erroné dans les fragments → chevauchement au réassemblage
LAND TCP/IP IP source = IP destination avec même port → boucle infinie
ARP Poisoning ARP (couche 2) Cache ARP empoisonné → man-in-the-middle entre deux hôtes
Scanners & Reconnaissance

Scanner actif

  • Envoie des paquets sur le réseau
  • Détectable par IDS/firewall
  • Plus d'informations récoltées
  • Ex : Nmap, scanner de ports

Scanner passif

  • Écoute uniquement le trafic existant
  • Indétectable (pas d'émission)
  • Moins d'informations mais discret
  • Ex : Wireshark, tcpdump
