POO FONDAMENTAUX
"

La Programmation Orientée Objet (POO) est un paradigme de programmation qui organise le code autour d' objets regroupant données et comportements. Les 4 piliers : Encapsulation, Héritage, Polymorphisme, Abstraction .

Vocabulaire fondamental

Classe

Un modèle / plan de construction qui définit :
→ Des attributs (données/état de l'objet)
→ Des méthodes (comportements/fonctions)
Mot-clé Java : class

Objet (Instance)

Un objet est une instance concrète d'une classe.
Créé avec le mot-clé new
Ex : Voiture v = new Voiture("Toyota", 2020);
On peut créer plusieurs objets d'une même classe.

Attribut

Variable définie dans une classe, représente l' état d'un objet. Chaque objet a ses propres valeurs d'attributs.
Ex: private String marque;
Ex: private int annee;

Méthode

Fonction définie dans une classe, représente le comportement d'un objet.
Ex: public void afficher() {…}
Ex: public String getNom() {…}

Constructeur & this

Constructeur

Méthode spéciale appelée à la création d'un objet.
• Même nom que la classe
• Pas de type de retour (ni void)
• Appelé avec new

this

Référence à l'objet courant . Utilisé pour distinguer les attributs des paramètres du même nom. Obligatoire quand il y a ambiguïté.

public class Voiture { // Attributs privés (encapsulation) private String marque; private int annee; // Constructeur : même nom que la classe, PAS de type de retour public Voiture(String marque, int annee) { this.marque = marque; // this = l'objet courant this.annee = annee; } // Getter (lit l'attribut privé depuis l'extérieur) public String getMarque() { return this.marque; } // Setter (modifie l'attribut depuis l'extérieur) public void setMarque(String marque) { this.marque = marque; } // Méthode d'affichage public void afficher() { System.out.println(this.marque + " - " + this.annee); } } // Utilisation dans le programme principal : Voiture v1 = new Voiture("Toyota", 2020); Voiture v2 = new Voiture("Renault", 2019); v1.afficher(); // Toyota - 2020 v2.afficher(); // Renault - 2019
Les 4 Piliers de la POO

1. Encapsulation

Cacher les détails d'implémentation. Les attributs sont souvent private , accessibles uniquement via des méthodes (getters/setters).
→ private / protected / public

2. Héritage

Une classe peut hériter des attributs et méthodes d'une autre classe. Évite la duplication de code (réutilisabilité).
→ extends

3. Polymorphisme

La méthode exécutée dépend du type réel de l'objet, même si la variable est de type parent. "Dispatch dynamique".
→ Override (redéfinition de méthode)

4. Abstraction

Classe non instanciable qui définit un modèle (interface). Force les sous-classes à implémenter certaines méthodes.
→ abstract

Modificateur Accessibilité Utilisation typique

protected Dans la classe + ses sous-classes Attributs/méthodes utiles aux filles
public Depuis n'importe où Méthodes de l'interface publique
BOUCLES JAVA
Les boucles en Java

While

int i = 1; while (i <= 3) { System.out.println(i); i = i + 1; } // Affiche : 1 2 3

For

for (int i = 1; i <= 3; i++) { System.out.println(i); } // Affiche : 1 2 3

Do-While

do { System.out.println(i); i++; } while (i <= 3); // S'exécute AU MOINS UNE FOIS !
Boucles imbriquées — Triangle d'étoiles
"

Une boucle peut être écrite à l'intérieur d'une autre boucle. La boucle interne s'exécute en entier pour chaque itération de la boucle externe.

for (int i = 1; i <= 5; i++) { for (int j = 0; j < i; j++) { System.out.print("*"); } System.out.println(""); // retour à la ligne } // Affiche : // * // ** // *** // **** // *****

HÉRITAGE
"

Héritage : mécanisme de la POO qui permet à une classe d'accéder aux attributs et méthodes d'une autre classe. La classe fille hérite de la classe mère. Mot-clé Java : extends

Vocabulaire

Relation "est une sorte de"

Un Employe est une sorte de Personne
→ class Employe extends Personne

Un Cercle est une sorte de Figure
→ class Cercle extends Figure

Accessibilité dans l'héritage

private → inaccessible dans les classes filles
protected → accessible dans les classes filles
public → accessible partout

// === Classe MÈRE === public class Personne { private String nom; // private = inaccessible dans les filles ! public Personne(String leNom) { this.nom = leNom; } public String toString() { return "je m'appelle " + nom; } } // === Classe FILLE === public class Employe extends Personne { private double salaire; public Employe(String leNom, double leSalaire) { super(leNom); // OBLIGATOIRE en PREMIÈRE INSTRUCTION ! this.salaire = leSalaire; } // Redéfinition (Override) de toString() : public String toString() { String debut = super.toString(); // appelle Personne.toString() return debut + " mon salaire est " + salaire; } } // === Utilisation === Employe e1 = new Employe("Sarah", 2000); System.out.println(e1.toString()); // → "je m'appelle Sarah mon salaire est 2000.0"
⚠️ super() doit être la première instruction du constructeur de la classe fille. L'héritage ne rompt pas l'encapsulation : l'attribut nom de Personne reste inaccessible directement dans Employe.
POLYMORPHISME
"

Polymorphisme : pour chaque objet, c'est la méthode de la classe réelle de l'objet qui est exécutée, même si la variable est déclarée avec le type de la classe mère.

Personne p1 = new Personne("Joe"); Employe e1 = new Employe("Sarah", 2000); Employe e2 = new Employe("Sunny", 1800); afficherPersonne(p1); // → "je m'appelle Joe" afficherPersonne(e1); // → "je m'appelle Sarah mon salaire est 2000.0" afficherPersonne(e2); // → "je m'appelle Sunny mon salaire est 1800.0" // La méthode reçoit un type Personne... public static void afficherPersonne(Personne unePersonne) { // ...mais exécute la méthode de la CLASSE RÉELLE de l'objet ! System.out.println(unePersonne.toString()); }

Principe clé

Variable Personne , objet Employe → c'est la méthode de Employe qui s'exécute. C'est le dispatch dynamique (liaison tardive).

Classe Object (java.lang)

En Java, Object est la classe mère de TOUTES les classes . Toute classe en hérite directement ou indirectement. Elle fournit des méthodes comme toString() , equals() .

CLASSES ABSTRAITES
"

Une classe abstraite est une classe qui ne peut pas être instanciée directement. Elle sert à factoriser des propriétés communes et force les sous-classes à implémenter certaines méthodes.

// === Classe ABSTRAITE === public abstract class Figure { // Méthodes abstraites : PAS de corps, juste la signature public abstract double getPerimetre(); public abstract double getAire(); // Méthode non-abstraite : partagée par toutes les figures public void afficher() { System.out.println("Aire = " + getAire() + ", Perimetre = " + getPerimetre()); } } // INTERDIT : Figure f = new Figure(); → ERREUR de compilation ! // === Classe concrète : Rectangle === public class Rectangle extends Figure { private double largeur; private double hauteur; public Rectangle(double l, double h) { this.largeur = l; this.hauteur = h; } // OBLIGATION d'implémenter TOUTES les méthodes abstraites : public double getAire() { return largeur * hauteur; } public double getPerimetre() { return 2 * (largeur + hauteur); } } // === Classe concrète : Cercle === public class Cercle extends Figure { private double rayon; public Cercle(double r) { this.rayon = r; } public double getAire() { return Math.PI * rayon * rayon; } public double getPerimetre() { return 2 * Math.PI * rayon; } } // === Utilisation avec polymorphisme === Figure f1 = new Rectangle(5, 3); Figure f2 = new Cercle(4); f1.afficher(); // Aire = 15.0, Perimetre = 16.0 f2.afficher(); // Aire = 50.26..., Perimetre = 25.13...
