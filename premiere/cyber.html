CHIFFREMENT
"

Le chiffrement sert à protéger des données en transit ou au repos. Mais un mot de passe … on ne doit jamais pouvoir le relire. → On utilise donc le hash , pas le chiffrement.

Chiffrement — Principes

Définition

Transforme des données lisibles ( texte clair ) en données illisibles ( texte chiffré ) à l'aide d'une clé . C'est réversible avec la clé.

Chiffrement Symétrique

Une seule clé pour chiffrer ET déchiffrer. Rapide mais problème de partage de clé.
Algorithme : AES (Advanced Encryption Standard)
Utilisation : chiffrement de fichiers, disques

Chiffrement Asymétrique

Paire de clés : clé publique (chiffre, partageable) + clé privée (déchiffre, secrète).
Algorithme : RSA
Utilisation : échanges sur Internet, signatures

HTTPS en pratique

Tunnel chiffré TLS entre client et serveur. Le MDP voyage chiffré pendant le transit mais doit être hashé avant stockage côté serveur.

Symétrique

  • 1 seule clé partagée
  • Rapide
  • Problème : comment partager la clé ?
  • Ex : AES-128, AES-256

Asymétrique

  • 2 clés : publique + privée
  • Plus lent
  • Clé publique partageable librement
  • Ex : RSA, ECDSA
LE HASH
Le Hash — Définition & Propriétés

Définition

Fonction mathématique qui transforme une entrée (de n'importe quelle taille) en une empreinte de taille fixe , sans retour arrière possible (irréversible).

Ce que le hash N'EST PAS

  • ❌ Pas du chiffrement
  • ❌ N'utilisez pas de clé
  • ❌ N'est pas réversible
  • ❌ N'est pas fait pour "cacher" des données

Propriétés clés

  • Même entrée → toujours même hash
  • Empreinte de taille fixe (256 bits pour SHA-256)
  • Irréversible en pratique
  • Résistant aux collisions (deux entrées ≠ même hash)

Algorithmes

MD5 obsolète — cassé
SHA-1 obsolète — cassé
SHA-256 recommandé (SHA-2)
bcrypt spécial MDP (lent intentionnellement)
SHA-3 moderne, alternatif à SHA-2

Limites du hash seul — Attaques

Attaque par dictionnaire

L'attaquant calcule le hash de milliers de MDP courants (123456, password, etc.) et compare avec les hashs de la BDD.

Rainbow Tables

BDD pré-calculées de correspondances Hash→MDP. Très efficace sans sel. Exemple : tables pour MD5 de plusieurs milliards d'entrées.

Même MDP = même hash

Sans sel, deux utilisateurs avec le même MDP "123456" ont un hash identique en BDD. Si un hash est trouvé → tous les comptes avec ce MDP sont compromis.

LE SEL
"

Le sel est une valeur aléatoire unique ajoutée au mot de passe avant le calcul du hash. Même mot de passe + sel différent = hash totalement différent.

Sans sel ❌

Michel : MDP = "AZERTY1234" HASH = 9B74C9897BAC770FFC029102 Bill : MDP = "AZERTY1234" HASH = 9B74C9897BAC770FFC029102 # IDENTIQUES ! DANGER ! # → Rainbow tables utilisables

Avec sel ✅

Michel : MDP + SEL unique "X8F!k" HASH = 9B74C9897BAC770… Bill : MDP + SEL unique "P9K@2" HASH = 700F74C989F74C… # DIFFÉRENTS ! ✅ # → Rainbow tables inutilisables

Caractéristiques du sel

  • Valeur aléatoire (générée à chaque création de compte)
  • Propre à chaque utilisateur (unique)
  • Stockée en clair en BDD avec le hash
  • N'a pas besoin d'être secret
  • Longueur recommandée : 16+ octets

bcrypt PHP (méthode recommandée)

// Hachage sécurisé (sel intégré automatiquement) : $hash = password_hash($mdp, PASSWORD_BCRYPT); // Stocke : $2y$10$SEL_ALEATOIRE...HASH... // Vérification lors de la connexion : if (password_verify($mdp_saisi, $hash_bdd)) { echo "✅ MDP correct — connexion autorisée"; } else { echo "❌ MDP incorrect"; }
✅ Résumé sel : Valeur aléatoire unique par utilisateur. Rend chaque hash unique même pour des MDP identiques. Stocké en clair. Rend les rainbow tables complètement inutilisables.
